# Промпт: надёжная работа Hub и административной панели

Ты работаешь с существующими Admin, Back-Hub и Hub-core. Улучши эксплуатацию системы после сбоев мониторинга, очереди жалоб и деплоя. Сохраняй архитектуру и пользовательские изменения. Работай в отдельных ветках; изменения сайта проверяй относительно актуального main, а не старого локального снимка.

## Выполнить в этом пакете

1. Мониторинг: независимые запросы состояния/графиков и времени использования. При ошибке сохраняй последний успешный снимок, показывай ошибку и время его получения. При смене периода не показывай данные старого периода. Не выдавай старый зелёный статус за свежую проверку, а сетевую ошибку — за подтверждённое падение сервиса.
2. Обновление: никаких пересекающихся запросов и лишних таймеров; скрытая вкладка приостанавливает автоматическое обновление, возвращение и восстановление сети запускают одну проверку. Ручной режим остаётся ручным. Ошибки localStorage и выход из fullscreen через Escape не ломают интерфейс.
3. Очередь жалоб: обновление текущих фильтров сохраняет строки и последний успешный timestamp. Ошибка обновления видна рядом с сохранёнными данными. Смена фильтра или страницы немедленно убирает данные предыдущего запроса; поздний ответ отменённого запроса не подменяет текущую очередь.
4. PostgreSQL: добавь интеграционную регрессию реального SQL очереди — приоритет в обе стороны, одинаковые приоритеты, стабильная пагинация, фильтры, counts и отсутствие приватных полей. Используй только явно настроенную локальную тестовую БД с изоляцией записей. Включи тест и существующие admin unit tests/build в CI.
5. Продакшен-деплой API: автоматически разворачивай только точный SHA успешного CI на main. Сериализуй деплои, используй образ с тегом SHA и проверкой revision. Миграции выполняй до замены работающего контейнера. Успех требует HTTP readiness и отсутствия перезапусков. При неудаче возвращай предыдущий образ и compose; деплой должен оставаться красным. Автоматически не откатывай миграции БД.
6. Прокси админки: nginx должен обновлять внутренний IP backend через Docker DNS после замены контейнера. Проверить восстановление без перезапуска Admin и сохранение пути/query API в контейнерном CI.

## Приёмка

- Значимые тесты проверяют сохранение и разделение снимков, отмену запросов, скрытую вкладку и ошибки обновления.
- Полные проверки Admin, сборки и backend CI проходят. PostgreSQL regression действительно выполняется в CI.
- В браузере проверить мониторинг, sidebar и очередь, включая имитацию ошибки запроса.
- Изменения оформить в PR; дождаться проверок, развернуть проверенные изменения и проверить фактический релиз.
- Зафиксировать ограничения: rollback образа не откатывает БД; текущий одиночный backend может кратко прерывать соединения при замене.

## Следующий пакет после этого релиза

- Довести открытый Hub-core PR200: корректные цели жалоб POST/COMMENT/MESSAGE, доступность формы всем нужным пользователям, понятные ошибки и локализация.
- Исправить управление блокировкой прокрутки несколькими модалками на актуальном main.
- Затем обсудить пользовательскую ценность: история инцидентов и уведомления, сохранённые раскладки монитора, SLA/percentiles и нагрузка, история действий модераторов. Не добавлять новые внешние сервисы без конкретной потребности.
